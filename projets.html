Situation Professionnelle 1 – Migration des fichiers utilisateurs vers OneDrive

Contexte :

Chez VINCI Airports, un vaste projet de modernisation de l'infrastructure informatique a été lancé. Il s'agissait notamment de faire évoluer l'ensemble des postes utilisateurs de Windows 10 vers Windows 11, dans le but d'améliorer la sécurité, la compatibilité applicative et la performance générale du parc informatique.

Cependant, un blocage technique majeur a été rapidement identifié : un nombre important d'utilisateurs, généralement les plus anciens dans l'entreprise, disposaient encore d'une redirection automatique de leurs dossiers Documents et Bureau vers un lecteur réseau local, le fameux lecteur U:.

Ce fonctionnement, hérité de pratiques anciennes, n'était plus compatible avec les standards de Windows 11, qui repose davantage sur une logique de stockage cloud via Microsoft 365.

Environnement :

  • Systèmes : Windows 10 (avant migration), préparation vers Windows 11
  • Réseau : Active Directory, GPO (stratégies de groupe), comptes utilisateurs centralisés
  • Outils : OneDrive, PowerShell, Excel, Outlook, GPO, documentation PowerPoint

Réalisation :

1. Recensement des utilisateurs concernés :

À l'aide d'un script PowerShell fourni et expliqué par un collègue (Antonin Desestre), j'ai détecté les utilisateurs dont les dossiers redirigés pointaient encore vers le lecteur U. J'ai intégré les résultats dans un fichier Excel pour identifier les utilisateurs prioritaires par direction (DSI, DRH, DAF, DOPS, DAIJ…), leur mail, leur numéro de téléphone et la taille de leurs données dans le lecteur U.

2. Communication avec les utilisateurs :

J'ai conçu un PowerPoint explicatif contenant : le contexte de la migration, les étapes de la procédure, les bénéfices de OneDrive, et les bonnes pratiques à suivre. J'ai ensuite rédigé un mail d'accompagnement clair et professionnel, que j'ai envoyé individuellement à chaque utilisateur concerné avec la présentation PowerPoint en pièce jointe.

3. Préparation et actions techniques :

J'ai ajouté manuellement chaque utilisateur dans les groupes AD nécessaires : "O_GPO_Exclude-Folder" pour exclure certaines redirections automatiques et "O_GPO_Redirect-Folder" pour forcer le comportement souhaité temporairement. J'ai ensuite déclenché la mise à jour des GPO via la commande 'gpupdate /force'.

4. Migration des fichiers vers OneDrive :

Je me suis rendu physiquement sur le poste de l'utilisateur à l'heure convenue. J'ai vérifié que OneDrive était bien activé et synchronisé sur le PC. J'ai copié manuellement tous les fichiers depuis le lecteur U vers le dossier OneDrive local, en veillant à conserver l'arborescence des fichiers.

5. Clôture de la migration :

Après validation du bon fonctionnement de OneDrive, j'ai retiré l'utilisateur du groupe "O_GPO_Redirect-Folder" pour finaliser le processus. J'ai mis à jour le tableau de suivi de migration dans Excel et ai informé mon tuteur de l'état de chaque migration.

Bilan :

La plupart des utilisateurs ciblés ont été migrés avec succès vers OneDrive, supprimant ainsi le blocage empêchant la transition vers Windows 11. L'approche personnalisée, combinant un support technique et une communication claire, a permis de réduire les réticences et d'assurer une transition fluide.

Ce projet m'a permis de développer des compétences techniques concrètes (AD, PowerShell, GPO, cloud), mais aussi des compétences humaines : écoute, accompagnement, autonomie et rigueur.

Situation Professionnelle 2 – Installation et configuration d'un contrôleur de domaine Active Directory et DNS sur Windows Server 2019

Contexte :

Lors de ma première année en BTS SIO, un des exercices pratiques consistait à installer et configurer un contrôleur de domaine Active Directory (AD) ainsi qu'un serveur DNS sur une machine virtuelle Windows Server 2019. Ce projet avait pour but de centraliser la gestion des utilisateurs, des groupes, et des machines dans un réseau d'entreprise, tout en assurant une résolution de noms efficace grâce au DNS intégré à Windows Server.

L'objectif était aussi de simuler un environnement réaliste, avec une infrastructure étendue : en plus du contrôleur de domaine, nous avons utilisé un serveur de fichiers distinct, nommé SRV-FIC, pour stocker et organiser les fichiers des utilisateurs de manière centralisée.

Environnement :

  • Système serveur : Windows Server 2019
  • Client : Machine virtuelle (VM) Windows 10
  • Réseau : LAN virtuel avec IP statique (10.0.206.x)
  • Outils : Active Directory, DNS, Gestionnaire de serveur, Outils GPO
  • Serveur complémentaire : Serveur de fichiers nommé SRV-FIC

Réalisation :

1. Création et préparation du serveur :

J'ai commencé par créer une machine virtuelle Windows Server 2019. Après installation, j'ai ajusté les paramètres de base : nom du serveur (AD-DNS) et adresse IP statique pour une communication fiable sur le réseau local.

2. Installation des rôles Active Directory (AD), DNS et DHCP :

Depuis le Gestionnaire de serveur, j'ai ajouté les rôles nécessaires : Active Directory Domain Services (AD DS) et DNS, indispensable pour la résolution de noms dans le domaine. Une fois les rôles installés, j'ai utilisé l'assistant de promotion du serveur pour en faire un contrôleur de domaine principal d'un nouveau domaine : GSBKD.local.

3. Configuration du DNS :

Une fois le domaine fonctionnel, j'ai configuré le DNS avec une zone de recherche directe : création d'un enregistrement A pour w19-ad-dns.GSBKD.local, ce qui permet au DNS de faire correspondre un nom de machine à une adresse IP.

4. Tests et vérification :

J'ai mené plusieurs tests pour valider la configuration : j'ai rejoint une VM Windows 10 au domaine, puis vérifié qu'un utilisateur pouvait se connecter avec un compte AD. J'ai également testé que la résolution inversée fonctionnait, en interrogeant une adresse IP et en recevant le bon nom DNS.

En parallèle, j'ai commencé à utiliser un serveur de fichiers séparé, nommé SRV-FIC, sur lequel les utilisateurs pouvaient stocker leurs documents.

Bilan :

Ce projet m'a permis de développer des compétences techniques solides dans :

  • L'installation et la configuration d'un contrôleur de domaine Active Directory
  • La mise en place et l'utilisation d'un serveur DNS
  • L'intégration de clients au domaine
  • La gestion de ressources partagées via un serveur de fichiers dédié (SRV-FIC)

J'ai compris l'intérêt d'une gestion centralisée des utilisateurs et des ressources, notamment à travers les stratégies de groupe (GPO) que nous avons abordées par la suite. Cette expérience m'a offert un aperçu concret du fonctionnement d'une infrastructure réseau en entreprise, et de l'importance des services comme AD, DNS, DHCP et les serveurs de fichiers dans l'organisation quotidienne du travail.
